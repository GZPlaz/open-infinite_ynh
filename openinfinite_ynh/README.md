# OpenInfinite for YunoHost

[OpenInfinite](https://github.com/GZPlaz/yunohost-new-app) generates printable math worksheets with answer keys and worked solutions, entirely in the browser — an open-source alternative to Kuta Software's Infinite series.

**Shipped version:** 0.1.0~ynh1

![Answer key with worked solutions](doc/screenshots/answer-key.png)

## Overview

The server only serves static files, so the app costs no CPU or memory beyond nginx and is a good fit for a Raspberry Pi. The app is generated in each visitor's browser: problems, worked solutions, figures, pagination and PDF export.

See [doc/DESCRIPTION.md](doc/DESCRIPTION.md) for the feature list and [doc/ADMIN.md](doc/ADMIN.md) for administration notes.

## Installation

The package sits in a sub-directory of the upstream repository, so install it from a local clone:

```bash
git clone https://github.com/GZPlaz/yunohost-new-app
sudo yunohost app install ./yunohost-new-app/openinfinite_ynh
```

You will be asked for a domain, a path (default `/openinfinite`), who may access it (default: visitors) and the default paper size for new worksheets.

## What the package does

| Script | Action |
| --- | --- |
| `install` | Downloads the pre-built release archive pinned in `manifest.toml` (sha256-checked), unpacks it to `/var/www/$app`, writes `config.json` from the settings, sets permissions (`$app:www-data`, 750/640) and adds the nginx config. No Node.js, no build. |
| `upgrade` | Fills in settings introduced by newer versions (`ynh_app_setting_set`), replaces the files with the new release (`--full_replace`, since bundle names are content-hashed), rewrites `config.json` and the nginx config. |
| `backup` / `restore` | The app directory and its nginx config. There is no server-side user data. |
| `change_url` | Moves the nginx config. Asset URLs are relative and nginx injects `<base href>` for the new path, so no files change. |
| `remove` | Removes the nginx config; YunoHost removes the directory, system user and permissions (manifest resources). |

`conf/nginx.conf` serves the app with:

- an SPA fallback (`try_files … __PATH__/index.html`) for client-side routes;
- a `<base href="__PATH__/">` injected with `sub_filter`, so deep links resolve assets from the app root;
- `Cache-Control: no-cache` on `index.html`, `sw.js` and `config.json`, so upgrades show up right away;
- one-year `immutable` caching for the content-hashed bundles and KaTeX fonts in `assets/`;
- `gzip_static on`, serving the `.gz` files produced at build time instead of compressing on every request.

## Manifest

YunoHost packaging v2 reads `manifest.toml`. `manifest.json` is an exact JSON mirror of it, generated by `tools/sync_manifest.py` (CI checks they match). Edit the TOML and regenerate the JSON.

## Testing

- `tools/test-nginx.sh /openinfinite` and `tools/test-nginx.sh /` render `conf/nginx.conf` like `ynh_config_add_nginx` does, serve the real build through nginx and check redirects, the base tag, deep links, `gzip_static`, cache headers and 404s (runs in CI).
- The scripts are linted with shellcheck in CI.
- `tests.toml` declares the default [package_check](https://github.com/YunoHost/package_check) scenarios (install at root and sub-path, upgrade, backup/restore, change_url, multi-instance) with the non-default A4 paper size.

## Releases

Pushing a `vX.Y.Z` tag runs `.github/workflows/release.yml`. It builds a reproducible `openinfinite-X.Y.Z.tar.gz`, publishes it as a GitHub release, and updates the `url` and `sha256` in the manifest. The manifest also declares `autoupdate.strategy = "latest_github_release"` for the YunoHost catalog's auto-updater.
